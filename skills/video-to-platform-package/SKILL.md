# video-to-platform-package

沿用这一个入口完成视频制作和交付，不另建一套同名流程。只处理用户选定的素材与平台；仅审看就交审看版，要求一路做完就继续已授权的普通步骤。完成剪辑或准备发布包不自动等于授权公开发布。

## 任务范围先确定

| 当前任务 | 必要交付与检查 | 不自动扩展到 |
|---|---|---|
| 仅审看 | 可连续观看的工程版本或用户要求的审看文件，改动与未完成项 | 最终交付导出、封面、平台文案、公开发布 |
| 局部修正 | 对应字幕／画面／声音改动，受影响区间预览与检查记录 | 重做全文转写、结构候选、无关素材或全量发布包 |
| 仅封面／文案 | 本期主题与目标平台所需的封面／文案，以及尺寸、文字、来源等对应检查 | 改旧片时间线、补全所有平台包装、上传发布 |
| 完整制作／发布包 | 按授权完成本页相关阶段；完整四平台包才适用现有结构校验器 | 未选择的平台发布、未授权外部操作 |

“审看版”不能只是几张静帧。需要可分享文件时做明确命名的草稿导出，不称最终版；若用户明确说不导出，就交工程连续预览。仅有截图和逐字稿时可给具体文本补丁／方案，缺可编辑源不能声称已修成片。

现有 `validate_content_package.py` 仅覆盖完整四平台包装，不能强套审看、局部修正、单封面或部分平台任务；这些任务按实际产物检查和记录范围，不为过校验补造无关字段、文件或 pass 状态。

下文描述完整制作路径；局部／独立任务只执行相关段落，涉及候选数量、三比例和发布产物时也以本表为边界。

## 规则归属与按需阅读

阅读顺序和用户没说时的默认值（工具、授权、片型、画幅、字幕、声音、预算、平台）以 [workflow 第 0 节](../../docs/workflow.md#0-开工前读什么用户没说时按什么做) 为准；本 Skill 不另列。ChatCut 执行／导出另读本目录的 [交付参考](references/chatcut-delivery.md)，实际发布读 [平台参考](references/platform-publishing.md)。

## 1. 确定输入和交付范围

核对源文件、当前工程、用户要审看还是导出／发布，以及原声、画幅、分辨率、封面、目标观众和平台。已经明确的不重复询问；缺失但不阻断的采用有依据的建议继续。ChatCut 剪辑只用 Desktop MCP，不用聊天框或 UI 点击替代项目操作；本地资产不当作已上传的云素材。

一条视频复用一个 `projects/<日期-名字>/`。根部保存 `packaging.json`、`asset-register.csv`、`audience-review.md` 与已有编辑计划；过程文件放 `platform-package/work/`，交付放 `platform-package/outputs/`。保留原文件校验信息，私人绝对路径仅留本机，不把原片和成片大文件提交 Git。

## 2. 读全文，定内容与 A-roll

使用本地转录能力，等待任务完成，保存全文和时间戳稿，修确定的识别错误。完整通读并确定受众、承诺、机制、边界和证据；新片保留至少三个有区别的结构候选并选一个。局部修正不重做无关策划。

按完整意思安排自然原声，预览脚本修改后应用，听剪口。资料研究可以此时开始，动画与普通字幕等 A-roll 稳定后再排。经验、推断、官方要求分清，不能用改写字幕偷偷更正口播事实。

## 3. 按句子需求搜索和落实素材

先写“原句／观众问题／画面任务”，查自有素材，再用对象、动作、字段和版本搜索一手来源。读取原文，核对适用条件和日期，采集必要清晰画面、脱敏并登记权利。具体搜索顺序和触发例子以内容包装规则为准。

真实经历用本人证据，官方入口只能证明入口；关系用自制图解，缺少成功结果不能生成补造。X／论坛经历不等于普遍规则。已有可靠来源和可读素材足够支持当前句子时停止扩搜；拿不到就明确缺口与替代方案。

定稿后绑定剪后语义窗口，复杂片可用 [visual-plan.csv](../../templates/content-package/visual-plan.csv)。对照需求、素材登记、实际入片、真实预览／最终文件，不能把搜到或导入当作用上。

## 4. 做可读画面、正常字幕和必要效果

从视觉编辑指南选择满足当前问题的最小处理：关键词强调、定义、局部放大、框选、人物缩窗、资料卡、清单、对比或流程图等。每项写使用理由和省略条件，原画面已清楚就不加。先检查真实样张中实际采用的图层，不为样张补造人物或资料，再批量。

这些是可选处理，不是效果配额。操作教程默认原画面＋正常字幕；观点 / 知识讲解片按 [片型](../../docs/visual-editing.md#先定片型) 的密度做讲解画面并配真实画面。都不反复叠“只是个人经验”大卡，不把每份核验来源都贴上屏。新增内容不能解决具体误解或操作缺口就省掉；能在现有画面轻量标注就不另盖卡，连续审看时主动删合并重复提示。

普通字幕以剪后原声为基准，仅修 ASR、术语和标点；解释、强调、更正独立。强调跟随完整关键词，保留否定和条件，不每词弹跳。优先保留原声，用清楚的补充解决轻度问题；关键事实会误导操作时删改或给用户具体补录选择，不能靠角落小字抵消。

电脑教程按可读性保横屏，黑边和手机插入重新排版；不套固定竖屏像素。姓名、邮箱、账户页脚、弹窗及嵌套截图使用独立遮挡，跟随位移、缩放和切换，检查边缘与相邻帧。隐私不靠字幕遮盖。

## 5. 新封面和自然平台文案

先定本片观看理由和一个视觉锚点，再写新 AI 生图提示词（默认用 `scripts/apimart_image.py`，用户本人的身份参考照片可作 `--ref`）；旧作品用于参考方法，不能默认只替换旧图文字。新提示词写清主体、层级、精确标题、人物身份参考、自然精修、留白、比例与不需要的元素。记录工具／模型、提示词、参考图用途与输出，先看生成结果再称可用。旧适配脚本仅在用户明确选择复用旧母版时使用。

完整包分别构图三比例：`3:4`、`4:3`、`16:9`；生成图的实际像素不一定等于 `packaging.json` 里的尺寸，选定后等比缩放并居中裁到准确像素（如 `sips -Z` 或 PIL），再跑校验；独立封面任务只做选定平台所需比例。保持主体和承诺一致，不拉伸或机械裁图。一个主判断、一个视觉锚点，标题两行以内，辅助字非必需。检查实际尺寸、缩小可读性和平台裁剪，不能把旧风格参数当唯一审美。

完整包为抖音／小红书／B站各留三个自然具体的标题候选和推荐理由、短长简介；独立文案任务按选定平台和范围做。X 单独写短帖，以当前编辑器的加权校验为准。自拟标题可用 `formula_id: original`，不虚构 DB 公式。写完读一遍，去掉报告目录、抽象套话和整齐排比。只承诺本片交付，不保证稳定、退款、审核或流量。推广自有项目才登记 `owned_links`；非推广内容留空，不复制默认广告链接。

## 6. 独立审稿与最终文件

独立观众只看标题、封面和成片／终稿，按时间码记录理解与观看阻力，P0/P1 修完再放行。逐字稿复核不能代替音画、动画或隐私检查。最终媒体检查方法以 workflow 为准；修改后复查受影响部分，不无故重跑已通过的无关工序。

仅在已授权范围内导出；排队不是完成。等待实际文件，核对尺寸、帧率、时长、音轨、字幕和完整解码，检查关键静帧与连续区间，保留 SRT 与最终 SHA-256。需要的分辨率工具没有枚举时，按交付参考选择可核验的转换；不把文件改名当成转换。记录抽样、时间映射、试听和全片检查各自范围及未覆盖项。

## 7. 逐平台提交与回执

只上传核验后的最终文件，按当前平台 UI 操作并核对本人账号；沿用本次已明确授权，协议、验证码等按当前工具规则处理。比例基线如下，现场要求变化时以真实预览核对：

| 平台 | 封面 |
|---|---|
| 抖音 | 横 `4:3`，竖 `3:4` |
| 小红书 | `3:4`，检查裁剪和信息流预览 |
| B站 | `4:3` 与 `16:9` 分别设置 |
| X | 有自定义入口才设置；否则如实记录默认视频缩略图 |

移焦后读回标题、正文、标签、声明、公开范围和封面。投稿结果未知先查同名作品，不重复点击；某平台阻断时继续其他不依赖的工作。

用 [回执模板](assets/delivery-status.template.json) 保存实际字段、成片校验值、比例、时间、状态、作品／管理链接、截图及待办。状态用 `draft / submitted / processing / published / failed / blocked / unknown / not_requested`。管理页明确已发布可记录该状态，但公开详情是否可访问单独记录；未取得可用分享链留空并给管理页，不构造链接冒充验证通过。材料 `ready` 不代表全部发布。

## 8. 交付、清理与复用

按“任务范围”交付，不要求每次全量产物。完整包保留全文及时间戳、`package-v2.md`、三比例封面、`final.srt`、导出核验、来源登记、审稿记录；发生投稿才有 `delivery-status.json/.md` 和发布凭证。仅审看、局部修正和封面任务只保留对应产物。已有同义字幕文件可记录映射，不为格式另造不同版本。

完整四平台包准备交付时运行 `python3 scripts/validate_content_package.py projects/<…> --ready`；它只检查结构与登记，不证明画面或事实。其他范围不要运行不适用的全量门槛。按实际任务交付审看版、局部修正、封面或成片；发生投稿时再交逐站入口／状态和凭证，检查边界及待办始终如实说明。

最终文件验证后按授权清理废弃／测试媒体；保留原片、工程依赖、最终版与来源，记录对象和空间。写本项目 review、真实 metrics 和台账。下一片参考历史判断与结果，不能复制旧标题、旧数字或旧封面。沉淀前搜索已有规则，合并同义项、修正冲突；技术参数只进工具参考。仓库变更走任务分支与 PR，未授权不合并。
