# ChatCut 成片交付的已验证注意点

本页只在任务包含 ChatCut 剪辑/导出时读取。调用前以当前 MCP 工具 schema 为准。

- 先取得当前项目和时间线身份，区分原片、旧剪辑和最终版本。A-roll 通过 `read_script` / `apply_script`，先 preview，再应用；上层视觉不参与语音剪辑。
- 要恢复现有片段外的词句，不能只延长已经截断的 Script 行。必要时保留旧时间线，从素材库原稿的语义区间重建新时间线，逐段核对结尾。
- 删除词句和清理静音一起操作后，复查句尾是否被截短。不要因工具应用成功就批量铺上字幕。
- `edit_item` 的图片资产引用若不可变，采用一次原子删除/新增替换，维持相同时间区间。修改/删除效果需带正确的效果类型和 ID。
- 预置推近效果可能有很强的默认缩放。用真实合成帧确认截图边缘和标题没有被裁；证据图不需要为了“动起来”强行推近。
- MG 动态字段按工具校验契约声明；这次校验器要求可识别的 `props = item.props`。不要把当前实现细节当作所有版本的固定 API。
- props 配置保存与静态校验通过，不等于实际渲染取得了字段。先检查缺省值、文字／坐标在开头中段和结束的真实输出；动态遮挡要检查移动区间。缺字段时修复声明或提供经过验证的缺省值，不因没有报错就视为遮挡有效。
- 字幕先做真实帧样张，再批量；宽度归一化字号会随画布变化。这次 2560×1440 中的 0.036 约为 92px，是本片验收值，不是所有画幅的默认值。缩小到手机宽度检查两行文本、标题及画面信息的相互遮挡。
- `local_export` 的任务 ID/预计文件路径只代表排队。等待文件完成并核对音视频流、实际时长，执行完整解码。当前导出若缺 2K 枚举，4K 原生导出后等比缩小为 2560×1440；不能把 4K 文件直接标 2K。
- 原生导出目录/文件对话框规则按当前工具处理，不绕过授权；保留最终字幕 SRT 和文件 SHA-256。
- 若最终交付另有缩放、遮挡或资料合成，版本关系、几何和音轨必须再查；不能只验原生导出。任务要求保留原声时，能无重编码保留就避免改动音频，必要时对比音频数据。素材重排时重新核对声音与视觉，而不是仅比较哈希。
- `preview_timeline` 可能返回 base64 图片。以图片块显示或保存，只输出紧凑元数据，避免把完整 base64 打进日志。
- 检查范围分开记录：逐字稿、采样帧、连续播放、试听、完整解码、平台转码结果。任何一项通过都不代替其他项。
