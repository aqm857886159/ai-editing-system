# L-016 横屏口播配代码讲解场景：先分区，再做画面，最后统一检查

来源：2026-10-24 最古老的学法（`projects/2026-10-24-ai-apprenticeship/`）。以下是做法，具体坐标、帧号和参数只属于那一片。

1. **先做一个代表性样张定版面。** 讲解区在一侧，人物缩成另一侧的圆角卡，底部留字幕带。样张确认后再批量做十几个场景，比做完再挪便宜得多。
2. **字幕放大会撞上所有场景的底部。** 那一片把字幕调大后，三个场景的脚注和计数行都被压住。改字幕样式后，要把每个场景最满的一帧叠上字幕重新看一遍。
3. **场景节拍取自剪后转写。** 每个元素的出现时间对齐口播里对应的词，A-roll 再剪就会错位；所以 A-roll 定稿后才渲染场景，改了 A-roll 就重排受影响的场景。
4. **同一个通用函数的缺省参数要测。** 入场函数在没有离场时间时算出 NaN，导致所有元素从第一帧就可见；只看中间帧发现不了，要看 t=0。
5. **钩子、叠加卡、B-roll 和讲解场景用一套视觉系统。** 字体、颜色、圆角、入场方式统一，全片才像一个作品。
6. **B-roll 按“证明 / 解释 / 情境”选来源。** 情境先找库存，库存没有的特定画面才用 AI 生视频，并标为示意；解释类一律代码画，不让 AI 画字。
7. **所有改动做完再导出，一次只导一个。** 那一片在改字幕前就开始导出，后来又导出一次，用户看到两个导出不知道用哪个。
8. **用户的成片反馈要分清改哪一层。** “人声小”先压音乐再做响度标准化；“有点慢”是用户的偏好，可以在定稿成片上统一变速、保留原速母版（见 [L-011](L-011-no-global-speedup.md)）；“想美颜”交给剪映，可以直接导出剪映草稿。
