# 视频评分卡：每片达到同一质感的检查标准

目的：每条讲解视频出来的质感一致，不靠当天手感。办法是三样东西一起用：
- 一套固定的组件库：[explainer-kit](../templates/explainer-kit/README.md)
- 一组自动检查：本页第 1、2 节
- 一张对着参考画面打的主观分：本页第 3 节

放行规则在第 4 节，执行顺序以 [workflow](workflow.md) 第 5 步为准。全套评分用于**观点 / 知识讲解片**；操作教程片和纯录屏段只过第 2 节的 P0 和第 1 节的声音，见 [视觉编辑指南 · 先定片型](visual-editing.md#先定片型)。

参考数据来自 [讲解组件总表](../research/creators/component-catalog.md) 中 5 位创作者、11 条视频的拆解。下面的区间是**发现问题的提示线**，不是越快越好：需要读、需要算的画面本来就该停得久。

## 1. 成片节奏（自动）

```bash
python3 scripts/score_video.py <成片或样片.mp4> --out projects/<片名>/score.json
```

| 指标 | 讲解类参考区间 | 超出时先查什么 |
|---|---|---|
| 每分钟镜头切换 | 6–22 | 低于 6：是不是整段口播没有画面变化，观众要一直盯着脸 |
| 镜头时长中位数 | 1.5–7 s | 高于 7 s：大部分时间画面不动，但需要读的地方除外 |
| 超过 8 秒的镜头占比 | 5%–38% | 高于 40%：长镜头是否都在讲解卡、公式这种值得读的画面上 |
| 最长静止段（freezedetect） | 讲解卡内不超过 6 s | 列出的每一段都要说得出理由，例如“观众在读公式” |
| 第一次画面变化 | 开头 3 秒内 | 开头先给观众看到结果或冲突，见 [观众与平台数据](audience-retention.md) |

- 场景渲染出来的单段样片只有一个镜头，这时**只看最长静止段**，镜头切换类指标对它没有意义。
- 已有数据：2026-10 的《大理论时代》口播精剪版，每分钟切换 1.4 次，超过 8 秒的镜头占 54%。这是“只有口播、几乎没有讲解画面”时的样子，可以作为反面基线。

同一条命令也输出声音指标，参考区间来自 [sound-reference.json](../research/creators/sound-reference.json)：

| 指标 | 参考 | 超出时先查什么 |
|---|---|---|
| 整体响度 | −10 到 −20 LUFS，目标约 −16 | 低于 −19：整体偏小，对成片做响度标准化，见 [声音](sound.md) |
| 峰值 | 交付前不超过 −1 dBTP | 超过：标准化时限峰 |
| 完全静音占比 | 0%–1.5% | 高于 1.5%：没有音乐垫底，或剪口留了死寂 |

## 2. 讲解画面体检（自动）

每个代码渲染的讲解场景都要过一遍：

```bash
cd templates/explainer-kit && node lint.js '页面.html#场景' [时间点...]
```

| 级别 | 检查 | 标准 |
|---|---|---|
| P0 | 文字进入字幕带 | 字幕带（y ≥ 880）以下不能有讲解文字 |
| P0 | 文字压到人物小窗 | 本片不用小窗时加 `--no-pip` |
| P0 | 字太小 | 换算到 1080p 不小于 22 px（`.en` 装饰小英文除外，它不承担信息） |
| P1 | 字号层级太平 | 最大 / 最小不到 2.5 倍；资料原文页可以例外 |
| P1 | 图形覆盖率低 | 字幕带以上，图形占画面不到 45%（参考创作者的讲解画面大多在 70% 以上） |
| P1 | 整段没有真实画面 | 照片、截图或视频一处都没有（图标不算）。讲解动画也要有真实画面锚点，规则见 [视觉编辑指南 · 素材从哪来](visual-editing.md#素材从哪来) |

`lint.js` 有 P0 时退出码为 1，不能进入批量制作。

## 3. 对着参考画面打主观分

先生成对标板，第一行是我们的画面，下面几行是参考创作者的画面（参考帧只在本地看，不入库、不进成片；新机器上没有这些帧，先用 `python3 scripts/creator_breakdown.py download` 和 `analyze` 按各创作者 `search-top-long.json` 里的作品重新生成）：

```bash
python3 scripts/reference_board.py --ours 样片.mp4 --ref xiaolinshuo linchao bidao --out projects/<片名>/board.jpg
```

打分不由做片的 Agent 自评：开一个新上下文，只给它对标板、样片和下表，按 [独立观众审稿](content-packaging/independent-reviewer.md) 的方式让它逐项打 1–5 分并给理由。作者可以对分数提出异议，但要写进 `review.md`。

| 维度 | 1 分的样子 | 5 分的样子 |
|---|---|---|
| 主线清楚 | 每张图各说各的 | 有一个贯穿全片的主视觉（公式、层级图、清单），观众知道讲到哪 |
| 真实画面 | 全是深色面板和字，看不到说的东西长什么样 | 每段都有真实截图、照片或视频；具体的东西用真图，抽象的用风格统一的生成图 |
| 当前项突出 | 所有元素一样亮 | 正在讲的那一项亮起、浮起，其余压暗 |
| 层次与深度 | 平面卡片放在纯色上 | 背景有层次（光晕、网格、颗粒），卡片有厚度，镜头有轻微倾斜 |
| 镜头在动 | 整段完全静止 | 慢推、拉回、视差一直在；需要读的时候停住 |
| 版面占满 | 小卡片孤零零在中间 | 图形占满安全区，字号层级明显 |
| 颜色有重点 | 颜色多而平均 | 一个结构色 + 一屏最多一处信号色 |
| 和参考同一档 | 放在对标板上一眼能看出差一档 | 放在参考画面中间不突兀 |

记录在项目的 `review.md`：分数、对应画面的时间点、最低分项打算怎么改。

## 4. 放行规则

1. **先做 3 个代表段**：一个整屏讲解、一个叠在口播上的、一个本片最复杂的。不要先铺全片。
2. 三段都通过第 2 节，**没有 P0**，并且每段都有真实画面（没有“整段没有真实画面”这条 P1）。
3. 主观分**每项不低于 3、平均不低于 4**，并且“和参考同一档”不低于 4。
4. 通过后再批量铺同类段落。批量完成后对成片跑第 1 节；改过的段落重跑第 2 节。
5. 不达标就改组件或设计系统，**改在 kit 里**，不在单片里打补丁。下一片自动继承。

分数和指标是发现问题的工具，不代表完播率。有了真实平台数据，再回来校准区间，写进 [观众与平台数据](audience-retention.md)。
