# 画面、字幕与效果：从观众问题选处理

适用于口播带录屏、软件教程和知识讲解。先完成 [workflow](workflow.md) 的转写与 A-roll；素材按 [搜索流程](content-packaging/README.md) 准备。外部创作者依据与适用边界见 [参考研究](content-packaging/creator-references.md)，以下具体用法是本仓库的执行规则，不冒充对方逐条原话。

## 先定片型

同一套规则用在两种片子上，画面密度不同。开工时先判断这条是哪种，片中某一段属于另一种时按段落处理：

| | 操作教程 / 录屏演示 | 观点 / 知识讲解口播 |
|---|---|---|
| 例子 | 软件设置、注册流程、代码演示 | 《大理论时代》、AI 学徒制、AI 求职，本系列大多是这种 |
| 观众主要看 | 屏幕上的真实操作 | 讲的人，加上把观点变成画面的讲解动画 |
| 默认画面 | 原录屏 + 正常字幕，只在找不到、看不清、会误操作的地方加 | 每段口播都配讲解画面或真实素材；只有开场钩子、个人经历、判断句这类“人就是内容”的时刻留全屏人物 |
| 节奏 | 跟着操作走，读页面时可以停很久 | 需要读的画面按读完的时间停，其余两三秒有一次画面变化（见本页“讲解组件”的节奏） |
| 放行 | `lint.js` 无 P0、连续审看无干扰 | [评分卡](video-scorecard.md) 全套：3 个代表段、对标板打分 |

两种片型都遵守下面“默认少加”的原则：每一层画面都要回答一个具体的观众问题。区别在于讲解片里“观众听不懂、记不住、想象不出来”的地方本来就多，所以画面多；它不是为了热闹而加。

## 默认少加，先判断值不值得打断

下表是可选处理，不是必须做满的清单；“让画面丰富一点”或“补一句个人经验”本身不足以触发加图。操作教程默认原画面与正常字幕；讲解片按上一节的密度做，但每个画面同样要说得出解决了什么问题。

加之前问：观众不看这层，会误解什么具体内容、找不到什么位置，或漏掉什么关键条件？答不出就不加。已有原声、字幕或页面讲清时，重复卡片应删掉。能在现有页面框选／高亮解决，就不再盖一张大卡；信息量较小的来源只作轻量出处，不让资料与讲述竞争。

不要反复打“仅个人经验”“不保证有效”“本片未证明……”这类泛化声明。原声已在讲个人经历，通常不另加贴图；确需交代范围时，优先融入开头语境或简介，一次说明即可。必要限定应具体回答本句条件，如“证件签发国与居住地分别填写”，而非不断撤回作者表达。同一事实边界不在相邻段落轮番提醒。

先给一个段落做减法审看：去掉贴图后是否仍听得懂、看得清、不会误操作？如果仍成立，就保留更简单的版本。确实影响操作的错误仍要处理，不能以减少贴图为由隐藏。

## 先决定这句话缺什么

逐字稿每个语义段先判断，再选最轻的处理：

| 观众问题 | 优先补什么 | 常用处理 |
|---|---|---|
| 不知道这是什么 | 一句定义、对象或实例 | 术语卡、对象截图 |
| 找不到你说的位置 | 页面整体位置和目标字段 | 局部放大、框选／聚光、短路径 |
| 关键结论需要看依据才理解／采信 | 必要且可读的原始依据 | 真实录屏、原文局部、注明口径的图表；出处可轻量呈现 |
| 分不清关系和顺序 | 对象、连接和分支条件 | 对比卡、流程图、逐步清单 |
| 记不住关键判断 | 本句最值得带走的短语 | 字幕内强调、独立大字卡 |
| 不知道现在讲到哪 | 当前步骤或章节 | 轻量步骤指示、章节转场 |
| 原声不够准确 | 明确的补充、限定或更正 | 同步更正卡；关键错误删改或交用户决定 |
| 已经清楚 | 无新增信息 | 保持原画面与正常字幕 |

不是每句都需要效果，也不为凑节奏机械切画面；讲解片的画面变化来自内容推进（下一个词、下一项、下一个数字），不是定时器。选择时写一句原因：这句话缺什么，为什么此素材／效果能补上；如果原画面就能完成，记录省掉效果。

## 效果选择表

### 文字与解释

| 处理 | 什么时候做 | 什么时候不做 | 时机与注意点 |
|---|---|---|---|
| 普通字幕内的关键词强调 | 本句有明确结论、对象、条件或关键数字 | 只是口癖、连接词，或每个词都想强调 | 在关键词发声时变字重／一种强调色；保留完整字幕和否定词，下一句复位 |
| 独立大字判断卡 | 一个转折、主要结论值得停下来记住 | 只是将整句字幕再放大一遍，或页面需要持续操作 | 一张卡一个判断；出现后留稳定阅读时间，别让普通字幕和大字同时抢焦点 |
| 术语定义卡 | 目标观众第一次遇到陌生词，如双重验证 | 后文每次提到都重复，或定义需要很长论文 | “名称＋一句人话＋必要实例”；随首次解释出现，后文仅需要时提醒 |
| 步骤／核对清单 | 口播确实有顺序或结尾能执行的项目 | 只是为了凑三条，或步骤存在未说明的分支 | 讲到哪项亮哪项；保留当前项与足够上下文，不提前标“已完成” |
| 对比卡 | 两个选项容易混淆，能用同一维度比较 | 对象不在同一条件下，或只有一边有证据 | 两侧对齐维度、单位、时间与条件；先说比较什么再揭示差异 |
| 流程／关系图 | 账户、对象、条件、先后关系用口头难以跟上 | 只是一两个步骤，真实页面已足够，或连线在暗示未证实因果 | 先给对象，再按讲述建立连接；主路径高亮，次要分支降级，符号和颜色含义一致 |
| 数据图／数字强调 | 有真实数量、趋势或差距需要比较 | 没有原数据，或滚动数字会制造虚假实时感 | 标单位、统计口径、时间与来源；动画不改变比例或隐去基线来夸大差异 |
| 补充／更正卡 | 有具体误解需要消除，如字段混淆或轻度错误 | 只想重复“个人经验”；已有语境已讲清；关键错误却只打算加角落小字 | 只写影响理解的正确判断，必要时标更正／出处，不重复泛化声明；细则见后文 |

### 页面、人物与真实素材

| 处理 | 什么时候做 | 什么时候不做 | 时机与注意点 |
|---|---|---|---|
| 局部放大／重构截图 | 字段、按钮、报错在实际观看尺寸下太小 | 原页面已清楚，放大会裁掉路径、条件或上下文 | 先给位置，再平稳移到局部并停住；需要下一步操作时返回足够范围 |
| 框选、箭头、聚光 | 页面同时有多个可能目标，观众不知道看哪里 | 鼠标已明确指向目标，或遮暗会隐藏必要说明 | 一次指一个目标；框不盖字、不冒充可点击 UI，页面移动时一起跟随 |
| 人物／原画面缩窗＋资料主画面 | 解释资料需要大空间，同时保留讲述者有帮助 | 网页被缩到看不清，人物窗压住操作，或仅为制造变化 | 先安排资料、字幕的可读面积，再决定人物窗是否保留；本段解释结束恢复主体 |
| 官方原文／真实录屏 B-roll | 讲具体入口、条款、过程或实际结果 | 只有品牌词相同、画面无关，或拿入口伪装成功 | 与相应句子对齐；保留标题、关键条件和来源，小字应推近放大而非塞整页，做法见“原素材上屏” |
| 真实前后／左右对照 | 同一对象的两个状态有可比证据 | 屏幕版本、条件、时间不同却未说明 | 标清前后和变量，差异与口播同步；未完成结果不能补一张虚构成功图 |
| 氛围／示意 B-roll | 情境或情绪有助于理解，且不会被当成事实 | 教程需要看清真实步骤，或“电脑／服务器”泛素材掩盖了关键内容 | 只作说明或气氛；必要时标示意，不能替代本人经历与事实证据 |

### 节奏与声音

| 处理 | 什么时候做 | 什么时候不做 | 注意点 |
|---|---|---|---|
| 裁切／景别变化 | 真实跳剪明显，或叙事重点发生变化 | 连续语音每段交替放大，脸和 UI 不断跳 | 默认直接切；缩放是可选修饰，不是按片段数自动执行，见 L-003 |
| 短章节转场／匹配转场 | 内容真正换章节、状态或对象 | 每句话加转场，或闪白／推拉掩盖没讲清的关系 | 用最少必要时间交代转换；图形匹配维持对象位置，不能转完找不到重点 |
| 逐步显现／轻量入出场 | 有先后顺序，或需要带视线进入某对象 | 静态已经清楚，或观众一直等动画才看到内容 | 快速引入后稳定阅读；避免全场同时移动、持续漂浮和夸张回弹（整屏讲解画面的慢推、视差除外，见 [taste](taste.md)） |
| 音效／音乐变化 | 章节转场、讲解元素出现、结论落定 | 每个字幕词都加音效，或教程口播被盖住 | 讲解片默认全片音乐垫底；音效对齐画面事件，不伪造支付／验证成功声音。完整规则见 [声音](sound.md) |

## 素材从哪来

**讲解动画也要有真实画面。** 口播负责让人听懂、想听，画面负责精确和证据：准确数字、原文、出处、换算都在画面上，口播说粗了的数由画面给准（写稿那一半见 [观众视角编排](viewer-flow.md#3-把知识讲出来通用手法)）。画面里，图形负责结构（谁和谁比、第几步、数字多大），真实画面负责“这是真的、它长这样”。每一段讲解画面至少有一个真实画面锚点：截图、照片、实拍片段或生成的示意图，放进组件里（词墙里的截图卡、清单项的配图、对比卡的实物图、图表背后的原始报告页），或在两个讲解段之间切一段全屏素材。整段只有深色面板和字，再精致也会单调，观众也不知道你说的东西长什么样。只有纯数据图可以例外，但来源页截图仍要出现一次。

### 每个画面需求，按这三问决定走哪条路

1. **这句话需要的是证明、解释还是情境？** 证明要真实来源；解释用代码渲染的组件做骨架，再配图；情境配照片或视频。
2. **它指向的东西在现实里存在吗？**
   - **具体存在**（某个人、某款产品、某个页面、某条新闻、某份数据）→ **只能搜**，用真实素材。不能生成一个“看起来像”的。
   - **一类通用情境**（工厂、教室、年轻人找工作、深夜加班）→ **先搜库存**；找不到合适的，或需要和全片画风统一，再**生成**。
   - **抽象概念、隐喻、假设或未来**（“大理论时代”“心理按摩产品”“信息茧房”）→ 现实里拍不到，**直接生成**。
3. **放在哪里、要不要动？** 放进组件里的用**静图**；两个讲解段之间的全屏情境用**视频**（3–6 秒）；需要证明“我真的做过”的用**本人录屏**。

| 需要 | 第一选择 | 第二选择 | 不要 |
|---|---|---|---|
| **证明**（我做过、数字是真的、出处在哪） | 本人录屏、截图、后台数据 | 官方原文、论文、新闻页截图 | 库存或生成画面冒充证据 |
| **解释**（概念、关系、过程、数据） | 代码渲染组件（[explainer-kit](../templates/explainer-kit/README.md)），配真实截图或照片 | ChatCut Motion Graphics 卡片 | 让 AI 模型画字或图表 |
| **具体对象的样子** | 搜：官方图、新闻图、平台截图、平台作品引用（`scripts/find_media.py`，记来源） | 自己拍或截 | 生成一个相似的假图 |
| **通用情境** | 库存实拍（ChatCut `search_stock_media`：Pexels、Pixabay、Unsplash） | 生成图或生成视频，套本片风格锁 | 可识别真人、品牌、真实产品界面 |
| **抽象概念 / 隐喻** | 生成图（进组件）或生成视频（做过渡） | 自制图形 | 用无关库存硬凑 |

搜索怎么搜、何时停，见 [素材规则](content-packaging/README.md)；去哪找、用哪个命令、怎么登记，见 [素材渠道](content-packaging/providers.md)；生成怎么写提示词、怎么保持全片一致，见 [generation-tools · 生成提示词模式](generation-tools.md#生成提示词模式)。

- **代码渲染**：一段解释超过约 8 秒、需要和口播逐词对齐、或同一视觉母题要在全片反复出现时用；组件里留好放图的位置
- **AI 生视频**：单镜头 3–6 秒，做转场和情境，不做主信息；先低清出样再出高清
- **库存**：只要通用情境就用库存，不花生成费；连续库存不超过一个镜头组，避免“素材感”
- **检查**：连续超过约 30 秒只有图形、没有任何真实或生成画面，就该补；这条也在 [评分卡](video-scorecard.md) 里自动检查

## 人物画面怎么处理

人物画面的状态由**这一刻观众该看谁**决定：

| 状态 | 什么时候 | 做法 |
|---|---|---|
| 全屏人物 | 开场钩子、个人经历、观点判断、结尾号召：此时人就是内容 | 原画面；需要强调一句判断时可推近一档 |
| 推近一档（约 110–120%） | 真实跳剪处，或一句需要停下来的判断 | 只在这两种时机用，不按片段交替（见 L-003） |
| 人物移到一侧 + 图解 | 解释需要画面空间，但表情和手势仍在传递信息；图解持续较长 | 横屏：人物裁成竖条或圆角卡放一侧（约 1/3 宽），图解占另一侧；竖屏：人物在上、图解在下 |
| 圆形小窗 | 资料必须几乎全屏才看得清（录屏、原文），人只提供声音连续性 | 放在不遮内容的角落；背景杂乱时圆形比矩形干净 |
| 全屏素材、无人物 | B-roll 盖跳剪、情境画面；或代码动画本身就是这段的讲解 | B-roll 单镜头一般不超过 4–6 秒；讲解型动画可更长，但要随口播推进 |

- 状态会持续好几句时，用平滑移动（约 10–15 帧）进出；只闪一下的 B-roll 直接硬切
- 横屏原片做竖屏版时，人物居中裁切，图解改成上下排布，不要把横屏图解缩小塞进去

## 先定版面分区，再做讲解画面

讲解画面、人物卡、正常字幕和叠加卡共用一张画布。批量做图解之前，先用一个代表性样张定下分区，之后所有讲解画面都按这套分区设计：

- **字幕带先留出来。** 先定字幕字号和位置，讲解画面的底部内容（脚注、计数、结论行）一律放在字幕带以上。字幕字号、行数或位置改了，要逐个讲解场景抽帧复查，不只看改字幕那一处
- **人物卡和讲解区不重叠。** 人物卡的位置和大小全片一致，讲解内容只用另一侧；叠加卡和 B-roll 也避开这两个区域，或在这段时间里明确接管整个画面
- **全片一套视觉系统。** 代码渲染场景、Motion Graphics 卡片和开头钩子用同一套字体、颜色、圆角和入场方式，观众才会把它们看成一个整体，而不是拼贴
- **讲解节拍跟着声音走。** 场景内部每个元素的出现时间取自剪后转写里对应词的时间，不按均匀间隔排；A-roll 再改动，就重排受影响场景
- **先看关键时刻的静帧，再整段渲染。** 每个场景至少看入场、讲解中、最满的一帧和离场前一帧，并且叠上字幕和人物卡一起看

## 讲解组件（从参考博主拆解得到）

来源：5 位创作者、11 条视频的拆解，汇总在 [讲解组件总表](../research/creators/component-catalog.md)（2026-10-26）。这里只留可迁移的用法，样式按本仓库自己的风格做，不复刻任何一家的外观。代码实现和参数在 [explainer-kit](../templates/explainer-kit/README.md)，每片从那里取，缺的组件先补进 kit 再用。

**原素材上屏：说到哪，指到哪，解释到哪。** 截图、原文、报表、网页、录屏、照片、实拍，凡是原素材进片，观众都只看到“有这么个东西”，不知道你说的是里面哪一处，也未必看得懂。所以每次放原素材都做三件事：

1. **对上位置。** 先把口播里说到的每个词，对到原素材里的具体位置（哪一行、哪个格、哪个按钮、画面里哪个人或物），写进场景参数，不凭感觉摆。
2. **标清楚。** 整体只露一眼（不到 1 秒，交代这是什么、长什么样），镜头随即推到那一处；说到那个词时画住它：高亮扫过、其余压暗、关键数字或对象再圈一下，同一帧配一个轻音效。推近后字在 1080p 下不小于 22 px，看不清就换更清楚的素材。讲到下一处就移过去再画一次，讲完拉回或切走，不让观众对着整页小字发呆。画住时框整行（表格一行、网页一整行），再圈出那个数或词；只框几个词，推近后看到的就剩一条缝。图表、目录要整张露着，只压暗其余。
3. **预判哪里看不懂，就地解释。** 逐处问：外文、缩写、专业名词、单位和币种、口径（季度还是全年、公司口径还是会计准则）、正负号和括号、截图里没交代的上下文。看不懂的地方贴一个标签，写中文名 + 原文名 + 原数 + 换算后的数，必要时加一句人话；原声说粗了或说错了的数，标签给对的。

报表、条款、网页截图用 kit 的 `docZoom`；实拍和录屏里指位置用 `callout`。

**全片主线。** 找一个能贯穿全片、随讲解一项项长大的视觉对象：公式、清单、路线图、对比表都可以。每讲完一部分就回到它、加一项或点亮刚讲完的那块，并写一句这块意味着什么，观众一直知道讲到哪里、还差什么；最后它就是值得截图保存的总结画面。给观众一个能自己代入数字或条件的工具，收藏通常更高。

| 组件 | 什么时候用 | 关键做法 |
|---|---|---|
| 定义卡 | 第一次给概念下“本片的定义” | 一句定义；读到哪个关键词，哪个词出现下划线或高亮 |
| 提问卡 | 需要观众停下来代入自己 | 一句问题，变量位置用问号；口播可以配一句“你可以先暂停想一想” |
| 大数字卡 | 一个具体数据第一次出现 | 情境画面压暗做底，正中一个大数字，单位、年份、口径小字放旁边 |
| 对比数字卡 | 两三个数字比较 | 并排，正在讲的亮、其余暗；讲到下一个时切换亮暗 |
| 结论条 | 一句要记住的判断 | 人物下方横条，关键词用色块标出，可加一个小标签说明条件（如“长期来看”） |
| 分类导航卡 | 进入并列的几个部分 | 全部项目一起出现，当前项亮起放大，其余变灰；每进入新的一项就回来一次 |
| 公式 / 结构图 | 全片主干 | 每一项下面配图标和中文名；新加的项用亮色标出；最后整体停留到能读完 |
| 链路图 | 有先后顺序的流程 | 按口播顺序一层层出现，讲完再整体展示 |
| 原文证据 | 引用报告、财报、条款等真实截图 | 用真截图（kit `docZoom`），按上面“原素材上屏”的三件事做，不整页摆着 |
| 层级图 / 编号清单 | N 层或 N 项逐项讲 | 编号一直可见，当前项亮、其余暗；讲完回全景，可在右侧加一列对比 |
| 比例对比 | 两个量级差很多 | 用面积对比，小的缩成点时用引线把数字拉出来 |
| 表格高亮 | 一张表只看一行或一格 | 其余行压暗，重点格加信号色描边，来源写在表下或角上 |
| A/B 对比 | 两种方案、前后效果 | 同尺寸、同裁切并排，上方标签，结论一句；全片同一样式，观众会形成“又在比”的预期 |
| 画面标签 | 指出录屏或实拍里某处叫什么 | 点 + 引线 + 标签，跟着对象，不另开一张图 |
| 引用叠层 / 名牌 | 不切走画面补来源，或第三方出场 | 叠在画面左下或人物旁，停在字幕带以上 |
| 外来素材框 | 别处来的视频、照片（新闻、发布会、采访） | 缩进窗口、四周压暗，左上角写出处；全片外来素材同一种框，和自己的录屏一眼分开 |
| 回放标签 | 关键的那一下观众第一遍没看清 | 先原速放完，再推近重放，挂“回放 · 0.5×”；可以加小窗放自己的反应 |
| 段落标签 | 一段讲某一种情况、某一把剑，时间较长 | 整段挂在角上，写编号和这段讲什么，可带进度点 |
| 人后大字 | 本章关键词第一次出现，人物在全屏口播 | 大字在人身后、人挡住一部分；一章最多一次 |
| 角色卡 | 讲某一方是谁、想要什么，几方之间的关系 | 卡里放真人、现场照片或 logo，旁边一两句诉求气泡；几方之间画一条关系箭头 |

**质感的检查。** 每片先做 3 个代表段，用 [视频评分卡](video-scorecard.md) 的自动检查和对标板打分，过线再批量。不达标就改 kit，不在单片里打补丁。

**节奏。** 需要读、需要算的画面停得久（10–20 秒都正常，按读完的时间定），其余地方两三秒换一次画面。情境 B-roll 跟着口播里的名词快切（约 0.5–2 秒），只给耳朵听到的东西一个形象，不承担信息。一个反常识数字之后，可以用 1 秒左右的反应镜头让观众喘口气，再进入下一段。

**人物状态** 按上文“人物画面怎么处理”的表选。讲解段之间回到全屏人物，让观众知道“这一段讲完了”。

**和观众说话。** 难的段落先承认难，可以告诉观众“嫌烦可以直接跳到结果”；需要代入时明确请观众暂停。这类话配提问卡，不要只停留在口播里。

## 字幕与强调的具体流程

1. **以剪后声音为时间基准。** 用源词区间到剪后时间的映射或当前时间线转写；删减、重排、变速后更新对应关系，不能搬源片时间码。
2. **先有正常字幕。** 保留说出的意思、否定词、限定条件和自然措辞；只改确定的 ASR 词、拼写与标点。不把摘要、事实改写或规避平台的谐音词当成“正常转写”。有真实隐私／内容问题时单独处理并记录，不能声称替词保证过审。
3. **按意思分卡和断行。** 不拆开姓名、术语、数字单位、否定与谓语。先设字号／行数，再修最终文字；重新分卡后重查。技术残字查 [L-001](lessons/L-001-asr-boundary-leak.md)，不能以清理残字为由批量删掉仍听得见的口癖。
4. **挑值得记住的最小完整短语。** 如“不是登录密码”，强调要包含“不是”，不能只把“登录密码”放大。数字带单位和条件；没有重点的卡保持普通样式。先用字重、颜色或下划线中的一种；独立大字只给主要判断。
5. **听关键词，再定入出点。** 不提前泄露结果、不在否定词之前制造反义；发声附近出现，读完再退出。动态入场不占掉全部阅读时间。先看一段真实连续预览，再批量同类卡。
6. **空间与时序一同验收。** 正常字幕、强调卡、来源和人物不能互相覆盖；用实际手机宽度检查可读性。SRT 是字幕，不包含视觉更正；导出副本与原生卡的清理差异要注明。

## 原声需要修正时

先区分 ASR 听错、原声口误、事实不确定和关键事实错误。前者按原声修字幕；后三者不能暗改成“说对了”的字幕。

- 次要口误／经验表达：先看语境是否已经明确，普通个人经历不额外贴免责声明。确实会被误读为普遍条件时，优先收窄一句具体判断或合并已有解释；需要更正才做清楚可读的独立提示，不一律升级成大卡。
- 身份、支付、退款、地区等操作条件：正确条件必须成为本段主信息，不用小字与强烈错误口播互相对冲。无法消除歧义就删掉该句或用现有原声重组；仍无法讲清时给用户具体待补录位置及原因。
- 官方页面只展示入口时标清入口；演示、示意、浏览器翻译、本人结果分别标示。不拼接虚假注册／付款／验证成功画面。

## 示例：一段教程如何决定素材与效果

以下是假设的双重验证教程设计，不是本次成片时间码，也不是任何产品的实际操作说明。入出点须在 A-roll 定稿后按真实声音定位。

| 原声／内容节点 | 先准备什么 | 最终画面动作 | 不该做什么 |
|---|---|---|---|
| “先看这个设置入口” | 查现有录屏；不足再搜“产品＋two-factor authentication＋official＋当前平台”并核验界面 | 先保留页面整体，再框目标；按钮太小时局部放大 | 用一个泛化的手机素材替代真实路径 |
| “它不是你的登录密码” | 定义有歧义时查官方说明，画一句解释 | 普通字幕照声音；强调“不是登录密码”，必要时给一句定义卡 | 只把“登录密码”变成大字，让无声观看产生反义 |
| “这两个账户用途不同” | 查两种账户的实际说明，先确定能比较的维度 | 临时缩小讲述者，主体位置放简洁对照，讲一侧亮一侧 | 两边填满小字，把操作页和人物都缩到看不清 |
| “帮助页这里写了条件” | 保存原文、日期、适用条件与来源，先脱敏 | 资料主画面，放大并高亮原句；读完后恢复 | 为突出结论裁掉限制条件，或持续推近不让人读 |
| “我已经提交了，但还在审核” | 本人真实提交与审核回执 | 显示真实状态和时间，普通字幕继续跟听 | 做“成功通过”动画或音效 |
| “最后再核对这两项” | 只保留刚讲过且确能行动的两项 | 随原声逐项亮起，读完结束 | 为模板再编第三项，或每项都加复杂转场 |

## 隐私：独立时间段和遮挡层

先检查原片、嵌套截图、标签页、账户页脚、弹窗、通知和手机状态栏，列明私密信息出现的区域与时间。遮挡与字幕／解释卡分轨，必要时锁定。可读文字用足够不透明的遮挡；模糊、马赛克和低透明图层要确认处理后确实不可读。

静止页面可固定遮挡；平移、缩放、滚动或页面切换时分段或跟踪，不把遮挡留在旧位置。检查出现前后、移动中、布局切换和结束相邻帧；更改任何变换后重查相应区间。不要只验几个中间静帧，也不要把某片的跟踪频率写成普适保证。含隐私信息的未遮挡原图留本地，不能为做封面上传给生成服务；用户本人获准的身份参考照片可以上传，见 [素材渠道 · 生成](content-packaging/providers.md#生成)。

## 一段处理完如何判断够了

从“观众看哪里、该理解什么、能读完吗、与声音一致吗”四点复查。先做代表性样张，再检查动态区间与最终导出；具体问题解决后继续交付，不为追求更多花样重复装修。无法证明提升完播率时，称它为改善可读性或减少理解障碍的设计选择。

同时做删减检查：是否被黑卡／文字盖住主内容，是否重复原声，是否每次出现都把观看方向拉走？连续看一个段落，有干扰就先删、合并或缩成轻量标注，而不是换一种动画继续保留。
