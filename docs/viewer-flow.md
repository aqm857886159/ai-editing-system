# 观众视角：一段素材怎么讲、怎么剪，观众才会一路看完

目标像滑滑梯：观众每一刻心里都有一个还没解开的问题拉着往下走，中间没有一处让人卡住（听不懂、在重复、跟不上）。这件事不能等发布后看数据才知道，开剪前就能按下面的原则排好；数据只用来校准。

本页回答“同一段素材，什么放开头、中间怎么推进、剪掉什么、调什么顺序、效果放哪”。依据有三类：
- **dbskill**：[dontbesilent 内容方法论](https://github.com/dontbesilent2025/dbskill)，主要是 `dbs-title-cover-intro` 和 `dbs-script-flow`，CC BY-NC 4.0，快照在 [dbskill/](dbskill/README.md)。
- **参考创作者拆解**：口播三人见 [talking-heads.md](../research/creators/talking-heads.md)；讲解类见 [毕导](../research/creators/bidao/breakdown.md)、[小Lin说](../research/creators/xiaolinshuo/breakdown.md) 的拆解。
- **讲述者本人**：讲述者的经历、反复出现的判断和说话方式，见 [讲述者画像](voice-profile.md)。写稿前先读。

观众为什么离开、各项数据对应什么心理，见 [观众与平台数据](audience-retention.md)。工序位置是 [workflow](workflow.md) 第 3–4 步：A-roll 定稿前做完本页第 1–5 节。

## 1. 先定这条讲给谁、卖什么

同一段素材可以讲成不同的选题，标题、封面和开头都是在替选题拉人。选题没定就写标题，只能靠夸大，观众点进来发现对不上就走。

做法（dbskill 叫“流量层级梯子”，这里用自己的话）：

1. 写下这段素材的**整片许诺**：观众看完拿走什么。可以是一个判断、一套步骤、一个故事，或一种体验。
2. 找出素材里**最抓人的具体细节**：数字、前后对比、反常的做法、亲历的场面、一句原话。之后标题、封面、开头至少要用上一个。
3. 想清楚观众会不会问“凭什么听你讲”。会的话，找一句能说出口的经历或数字，例如做了几年、做过多少、什么结果。
4. 写 2–4 个选题候选。第 1 个用原话，后面每个只改一处，让它讲给更多人或让同一群人更在意：
   - 删掉不必要的标签和行话；
   - 把行业词换成观众自己的说法，比如“skill”换成“AI 技能包”；
   - 挂到素材里已经露过头的大话题上（赚钱、工作、家庭、关系、自我价值）；
   - 换成更大的一群相关的人。
5. 每个候选过四项，过不去就退一步：
   - 素材能不能兑现；
   - 来的人是不是我们想要的观众；
   - 评论区会不会全在吵别的事；
   - 离素材太远、像不像空话。
6. 选一个，写进 `edit-plan.md`。写的时候连同它的标题示例和“前 10 秒说什么”一起写。

本账号的数据给了两种已验证的形状：
- **一个具体故事撕开一个认知。** 《回村后，我又悟了》：115 万播放，收藏率 3.36（中位数 0.29）。
- **一套能截图带走的步骤。** 《降龙七步》：15 万播放，收藏率 3.21。

新片先看素材更像哪一种，往那个方向包装。

## 2. 素材地图：先给每段打标签

完整读逐字稿，按意思切成段（一般 20–60 秒一段），每段写一行：

| 段 | 原话起止 | 功能 | 抓人的细节 | 依赖 | 强度 1–3 | 处理 |
|---|---|---|---|---|---|---|
| | | 结果 / 判断 / 故事 / 证据 / 演示 / 方法 / 铺垫 / 重复 / 跑题 / 口误重来 | 数字、对比、原话、画面 | 观众要先懂哪段 | | 前置 / 保留 / 压缩 / 删 / 待核实 |

另外单独列出：
- **开头候选**：最强的结果、冲突或判断，标原话位置。
- **能被转述的一句话**：一个新名字、一个重新下的定义、一个类比。
- **需要证据的说法**：交给素材搜索，见 [素材渠道](content-packaging/providers.md)。
- **能单独切成短视频的段落。**
- **隐私风险的位置。**

后面的排序、剪辑、找素材、做效果都从这张表出发。

## 3. 把知识讲出来：通用手法

知识内核本身没问题时，问题通常出在“怎么说”。下面这些做法在参考创作者里反复出现，挑适合本片的用，不用每条都上：

| 手法 | 做法 | 例子（见拆解） |
|---|---|---|
| 第一句就是判断或结果 | 标题级的一句话直接开口，不问好、不自我介绍、不交代背景 | 谢胜子“不要懒”；dontbesilent“只要你现在不是在执行手头的动作，就是在逃避” |
| 先讲一个具体的人和事 | 一个人、一个场面、一个前后对比，判断后出 | 萌妞妞从一封临终前的信讲起；我们的爆款从“我哥们儿”讲起 |
| 替观众先问 | 把观众心里的疑问说出来，再给有数量的承诺 | “怎么可能年入千万？总共三条路” |
| 起一个名字、或重新下定义 | 给现象起名，或把一个常用词切成两半 | “替代性行动”；“懒得舒服是放松，懒得不舒服才是懒” |
| 对照清单 | 两列特征一一对照 | 真正的执行 4 个特征 vs 替代性行动 4 个特征 |
| 例子先于概念名 | 先举两三个生活里的例子，最后才说它叫什么 | 毕导先讲菜价、工资、作业，再说出定律的名字 |
| “按理说……实际上……” | 先说观众以为的，再给反过来的事实 | 毕导：价格首位数字按理平均分布，实际 30% 是 1 |
| 类比 | 用一个能感觉到的场景代替抽象的道理 | 萌妞妞用“离婚登记处挂孩子的问句”讲一句广告语有多伤人 |
| 替观众提反驳 | “有人会说……”，自己接住 | dontbesilent、小Lin说、毕导都在用 |
| 让观众代入 | 让观众暂停算自己的数，或想自己的处境 | 小Lin说“暂停一下想想你每月要花多少” |
| 亲历做证据 | 自己家的事、自己的弯路、身边人的原话 | 谢胜子讲当年错过公众号；萌妞妞讲家里饭后聊天 |
| 背书一句带过 | 只用一句说出凭什么听你讲 | “七个平台都从零做到一万粉” |
| 给正面对照 | 批评之后给一个做对了的例子 | 萌妞妞批完广告语，举“来了就是深圳人” |

四条底线：
- **一条一个核心判断。** 其余都在证明、展开或应用它。观点短片一两分钟讲完；讲解长片也只围绕一个判断，用多个例子反复印证。用户一个题目只录一条长片；题目大、有几个核心判断时，长片按章节写，每章一个判断，再按第 8 节拆开发。
- **信息密度靠改句子，不靠加话。** 观众说听不懂，往往是先说了一句听不懂的话，再用两句废话解释它。把那一句改成能听懂的话，删掉那两句。术语出现时，后面紧跟一句大白话。嘴和画面分工：口播负责意思、比方、情绪和结论，精确数字、外币原数、汇率、清单和日期交给画面。口播只说取整后的数，一句最多一个新数字。必须说准的几句（开头、定义、带分寸的结论）写成能背下来的短句，分寸放进结论句本身，比如“账面巨亏，生意开始赚钱”，不靠后面一串“但是”。2026-10-27 那条 ① 账，第一章约 3000 字带了 92 个数字，用户复述时说错的数和说过头的话，都出在让嘴扛精确和长限定的地方。
- **原文里的名词要正面回应，不能只换成比喻。** 讲财报、文件、产品时，观众会在新闻里、原文里看到那个正式名称。例子讲完要回到原名，把名字拆开，每一块对到例子的哪一部分；名字里的“等”“其他”“调整后”也要说清包括什么。英文原文配截图。外文专有名词（股票类别、机构、公司类型）口播里说一次英文原名、画面上中英并列；中文译名和常用词撞车的要点明区别，比如 Class A 说成“A 类股”，并说明它不是中国的“A 股”。比如“可转换票据等的公允价值变动”，拆成可转换票据、等（另外两种约定）、公允价值、变动四块，逐块对到借条例子上。
- **讲结构先给一张图，一段新名词不超过三个。** 股权、组织、流程、制度这类内容，不按原文的清单顺序一项项念（A、N、T、F、E 五类股挨个讲，每类再说票和钱，念的人和听的人都会丢）。先画一张图：有哪几方、各自手里有什么、管什么；再沿观众的一个问题（“谁说了算”）走一遍。图上的基本角色（股东、董事会、CEO 这种）也别假设观众懂，先用生活里的对应物讲一遍再对回原名，比如小区的业主选业委会、业委会请物业、大事业主投票（2026-10-27 用户就卡在这三者的关系上）。和这个问题无关的角色、规则、英文全称只放画面或删掉；上一条要求的原名，只对观众会在新闻和原文里碰到的那几个。每章要有一个能贯穿到底的例子或画面，第一章的借条就是。每加一轮内容，就把这一章重读一遍，删到时长预算以内。

已经拍完、不能补拍时，这些手法用在**剪辑和画面**上：从原话里挑第一句，把例子移到概念名前面，给对照清单做成画面，用字幕外的叠字说出名字。需要新口播时，列成补录建议交给用户，不冒充原话。

## 4. 排顺序：开头、中段、结尾

### 开头（前 30 秒）

| 时间 | 要做到 |
|---|---|
| 0–3 秒 | 第一句和第一个画面就说清“这是关于什么的什么”：结果、判断、事件或疑问，选素材里最强的一个 |
| 3–10 秒 | 说中观众的处境（“你是不是也……”），亮出背书或那个最抓人的细节 |
| 10–30 秒 | 给出承诺：看完能得到什么；可以说有几步、几个原因，但不在开头列一二三 |

- **不要假设观众看过标题。** 开头自己交代清楚在讲什么；标题负责让人好奇，开头负责直接往下讲。
- **冷开场**：从素材后面挑原话前置时，每多一段都要推进同一个观看理由（多一个异常事实、多一层冲突），不要连着堆数字和形容词。前置后看原位置：还承担重新开始那一段的作用就保留，只是重复就缩短或删掉，写进剪辑计划。拼接处要听语气、背景声、姿态是否接得上。
- **不要这样开头：**
  - “大家好，我是……今天给大家分享……”；
  - 先讲背景再讲事；
  - 只有“一件事”“一个秘密”却不说是关于什么。

### 中段：一条问题链

- **每段第一句是观众此刻心里的问题，最后一句收住，再抛出下一个问题。** 毕导一条 12 分钟的视频就是四个问题接力：
  1. 为什么时间越过越快？
  2. 为什么我们用对数感知？
  3. 为什么自然数据首位多是 1？
  4. 凭什么成立？
- **约每 40–60 秒一个落点：** 一个反预期的事实、一个证据、一个演示或一句判断。两个落点之间不超过一分钟的纯铺垫。
- **难的地方先承认难，** 允许观众跳过（“嫌烦可以直接跳到结果”），反而更多人留下。
- **故事和道理交替。** 连着讲三段道理，中间插一个具体的人或场面。

### 结尾

- 兑现开头的承诺，回扣开头的那个人、那句话或那个问题。
- 留一个能截图保存的画面（步骤、清单、公式），或一句能转发的话。
- 评论引导问一个具体、好回答的问题。
- 承诺兑现后就收，不再开新话题；“下期再见”可以留，但不能只有它。

## 5. 剪什么、调什么顺序

**删：**
- 同一个意思说了两三遍，只留最有力的一次；
- 观众已经懂了还在举的例子；
- 说了等于没说的话；
- 开头的寒暄、自我介绍和预告；
- 口误重来；
- 和整片许诺无关的支线。

判断一段是不是跑题前先问：删掉以后，观众在下一个关键点还能自己想明白吗？想不明白，它就是必要的论证，不是赘肉。

**不删：**
- 限定条件；
- 支撑主判断的那个例子；
- 建立可信度的经历；
- 正常的呼吸和停顿。

缩短时长靠删整段，不靠句内抠字，见 [0003](decisions/0003-aroll-continuity-over-length.md)。

**调序：**
- 最强的结果或判断前置成冷开场；
- 例子挪到概念名前面；
- 最有力的证据放在观众最可能起疑的那一句之后；
- 散在各处的同一条支线归到一处；
- 结论不要在中段提前说完，否则观众得到答案就走；
- 能截图带走的步骤或清单放在最后。

**每次调序后，读剪后逐字稿的接缝：** 上一段最后一句和下一段第一句之间缺不缺一句承接。缺的话，优先从素材里找现成的话；找不到就用画面或叠字补上，不靠转场掩盖。

## 6. 效果放在注意力的哪个点

画面效果的位置由第 4 节的结构决定，不是平均撒。具体做法见 [视觉编辑指南](visual-editing.md)：

| 结构上的位置 | 画面上做什么 |
|---|---|
| 第一句、第一个画面 | 首帧就有动作或大字，和封面说同一件事 |
| 每个落点（反预期、证据、判断） | 画面变化跟着落点走：大数字卡、证据原文、判断条；音乐可以停半拍 |
| 新名字、新定义第一次出现 | 定义卡或叠字，让观众能记住、能转述 |
| 对照清单、步骤 | 做成讲到哪亮哪的画面，最后整体停留，方便截图 |
| 故事里的人和场面 | 真实素材或示意画面，见 [素材从哪来](visual-editing.md#素材从哪来) |
| 一段讲完、换下一个问题 | 回到全屏人物，或一个短的段落标题 |
| 观众要认真听一句复杂的话时 | 画面保持简单，不同时上复杂动画 |

## 7. 剪完的滑梯检查

在剪后逐字稿和样片上做，A-roll 定稿前和成片导出前各做一次：

1. **每段第一句连起来读。** 只读每段第一句，应该能听出一条完整的问题链；读不通就是顺序或承接有问题。
2. **冷读前 30 秒。** 不看标题，只看前 30 秒：能不能说出这条讲什么、为什么值得看完？
3. **逐段三问**（参考 `dbs-script-flow`）：
   - 和上一段之间有没有跳跃；
   - 这段有没有在重复或绕圈；
   - 有没有一口气念不完、太书面或没解释的术语。

   标出观众最可能划走的位置，按高、中、低风险排序，先改高风险。
4. **承诺一致。** 标题、封面、开头是不是同一件事，正文是不是兑现了。
5. **换几个观众读。** 用 [独立观众审稿](content-packaging/independent-reviewer.md) 开新上下文，按平台换 2–3 种观众：完全新手、同行、刷到的路人。每种各说会在哪一秒走、为什么。

## 8. 一条长片拆成几条

用户一个题目只录一次长片，不分集录。要让它既能整条发，也能拆成几条独立的片子，写稿时就要按下面做：

- **按章节写，每章一个核心判断。** 每章 5–10 分钟，有自己的问题链和落点。
- **每章第一句能当冷开场。** 不用“刚才说了”“接下来”开头。章节之间的承接句单独成一句，标成“长版专用”，拆片时直接剪掉。
- **每章最后一句能当结尾。** 一句能截图的结论，或一个评论问题。
- **前面章节讲过的概念，后面再用到时补半句解释。** 拆开后观众没看过前一章。
- **稿子后面附拆分表**，写清每条片段：
  - 从哪句到哪句；
  - 单独发时的标题和开头一句；
  - 要不要补一张开头字卡；
  - 预计时长。

  拆分表分两类：
  - **章节片段**：一章一条，适合 B 站和小红书长视频；
  - **高光片段**：1–2 分钟，一个反常识的事实加解释，适合抖音。
  - **系列**：章节片段在同一平台按顺序连发，进合集。一章太长（超过约 10 分钟）就在小节边界再拆；集与集之间的“下一集讲……”和某集缺的冷开场，写成补录句，正片录完同一次接着录，不另约录制。
- **用户看着稿子用自己的话讲，不逐字念。** 只有开头、定义和结论那几句短句要说准，其余都是复述。稿子按 [讲述者画像](voice-profile.md) 第 4 节写成讲述者会说的话。所以稿子要能被复述：
  - 交稿时同时给只有口播文字的朗读版 `script-read.md`：没有画面提示、待确认和表格，用户看稿先看这一份。用 `python3 scripts/make_read.py projects/<片名>` 从 `script.md` 生成，改稿后重跑。
  - 交稿时每章附一张录制提纲：每段一句骨架，加上这一段要说的数字。数字取整，单位写全（亿元还是亿美元）。
  - 录之前，用户不看稿，用三四句话讲出每章的骨架。讲不出来，问题在稿子，先改稿再录。
  - 每录完一章，对着提纲核一遍数字。说错的当场补录这一句。
- 剪辑时先剪完整长片，再按拆分表从定稿时间线上复制出片段，每条单独过[滑梯检查](#7-剪完的滑梯检查)的“冷读前 30 秒”。
