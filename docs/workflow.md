# 口播与屏幕教程制作流程

拿到一条新原片，从本页第 0 节开始，按顺序做。本页负责工序和放行条件；[素材规则](content-packaging/README.md) 负责搜索与证据，[视觉编辑指南](visual-editing.md) 负责效果、字幕、更正和隐私，[发布 Skill](../skills/video-to-platform-package/SKILL.md) 负责交付与逐平台执行。不要在多个入口各写一套流程。

先读用户已作出的决定：仅审看还是允许最终导出／发布、画幅、原声、封面与平台。沿用当次已明确的授权，普通步骤自主完成；需要选择时给具体样张和建议，不逐工序重复询问。审看要交可连续观看的工程或审看文件，不能用几张静帧冒充；用户明确禁止导出时只交工程连续预览。用户要求审看文件时可做必要的草稿导出，注明版本与未完成项，不据此最终交付或公开发布。工具调用以当前 schema 为准，参数笔记见 [ChatCut MCP](tools-chatcut-mcp.md)。

只修字幕、做封面或调整局部时，执行对应工序和受影响范围；不重做无关的全文策划、素材搜索或发布包。产物与校验范围由发布 Skill 的“任务范围”表维护。

## 1. 登记来源与观看目标

- 建立或复用一个项目目录；核对 ChatCut 当前项目、时间线、原片和旧版本。
- 登记本地源文件、校验值、时长、尺寸、帧率、音轨与素材角色；原片不复制入 Git。
- 口播、人像、电脑录屏、手机插入分别辨认。电脑教程保留适合看清网页和白板的横屏；原片有黑边先查来源及缩放，不直接裁掉内容。
- **FocuSee 录制要用原始工程，不要只用导出版。** 用户给的 `.mov` 往往是 FocuSee 导出版：去过停顿、烧了字幕、人像缩成了小窗，人像不能从里面裁。原始工程在 `~/Movies/FocuSee Project/<名字>.focusee/recording/`，摄像头、屏幕、麦克风、系统声音分开存。按下面做：
  1. `python3 scripts/focusee.py list` 列出全部工程，按录制时间和时长找到这条片（导出版文件名里的日期、用户说的大概时长）。不是每个工程都有摄像头，有的摄像头是竖拍，`list` 里会写。
  2. `python3 scripts/focusee.py prep "<工程名里的一段>" --out projects/<片名>/media/focusee`：按 `metadata.json` 里各轨的开始时间对齐，输出 `aroll.mp4`（摄像头画面 + 麦克风）、`screen.mp4`（屏幕，和 aroll 同一时间原点）、`mic.wav`（给 whisper 出逐词时间）。约 20 秒。系统声音默认不混；软件提示音是内容时加 `--with-system-audio`。
  3. 在 ChatCut 里 `push_asset` 导入 `aroll.mp4`（要用屏幕时连 `screen.mp4` 一起），之后转写、A-roll 都只对 `aroll.mp4` 做。
  4. A-roll 定稿后，哪一段要看屏幕，就在上层轨道加 `screen.mp4` 的条目，`sourceIn`、`startFrame`、`durationFrames` 照抄下面那段 A-roll 条目（`read_project` 能读到）。两个文件时间原点相同，所以逐段对得上，人声和画面不会错位。
  - 用户只有导出版、找不到原始工程时，就用导出版剪；人像需要干净画面而导出版里只有小窗时，用两边转写逐词对齐来映射，做法见 `projects/2026-10-09-big-theory-era/work/map_camera.py`。
- 写清目标观众和看完能做的一件事。出口：知道剪哪份素材、交付给谁、做到哪一阶段。

## 2. 完整转写与语义审读

使用本地 ChatCut 转录能力（`trigger_transcript` → `track_progress`），等待任务完成，保存全文与时间戳稿；先通读再改。讲解画面的节拍要逐词时间，而且要的是**剪后**时间：A-roll 定稿后，导出一版只含声音的审看草稿（或从时间线导出的 A-roll），转成 16 kHz 单声道 wav，再用本机 whisper 转：

```bash
ffmpeg -i aroll-cut.mp4 -ac 1 -ar 16000 aroll-cut.wav
whisper-cli -m ~/.cache/whisper-cpp/ggml-large-v3-turbo-q5_0.bin -l zh -ojf -of work/aroll-cut -f aroll-cut.wav
```

`-ojf` 输出带逐词时间的 JSON；场景里每个元素的出现时间取自这里。按关键词查时间可参考 `projects/2026-10-09-big-theory-era/work/wordtime.py`。检查开头、重复、跳转、陌生术语、模糊因果、具体操作和结尾，估算语速。

按原音修 ASR，术语结合上下文及 [词典](lessons/L-010-asr-dictionary.md)；有歧义再核对原音或资料，不做全局盲替换。口播事实错误单独登记，不能通过改字幕假装说对。出口：逐字稿可靠，已分清识别错与内容错。

## 3. 内容结构与素材需求

新片写内容内核，按 [观众视角编排](viewer-flow.md) 第 1–2 节定选题、给素材打标签，再比较至少三种有实质差别的结构并选定一种（排法见第 4–5 节）；只改现有字幕／局部镜头时不重做整片策划。先记录语义锚点，定稿后换算为剪后时间，避免拿源片时间直接贴图。

逐段问：观众哪里不懂、看不清、不信、记不住、不会操作？每一段讲解画面同时写下它的真实画面锚点，以及走自有、搜索、库存还是生成（规则见视觉编辑指南“素材从哪来”）；需要生成的，先写本片 `style-lock.md`。在现有 `edit-plan.md` 中记录，复杂片可用 [visual-plan.csv](../templates/content-package/visual-plan.csv)。每项写原句、观众问题、画面作用、候选效果、素材需求及不用效果的条件。没有理解障碍的段落允许保留原画面。

素材搜索可在此开始：先查自有素材，再按主张搜索官方来源；核验、采集与来源登记遵循素材规则。A-roll 未定稿前只准备资料，不批量排动画、字幕和最终入片时间。

## 4. 定 A-roll

先预览脚本差异，再应用。优先按句子或完整意思删减与重排，句内只处理明显重复、口误或长停顿；试听剪口，必要时恢复连续原声。强钩子可前置，但不能拆掉限定条件或强行从结尾抽一句。

人声有底噪或回声时，此时先做人声处理，见 [声音](sound.md)。保留自然呼吸，长停顿阈值根据实际听感调整；不机械使用停顿阈值，默认不整体加速。用户明确要求整体变速时，放到最后在定稿成片上统一处理（保持音高），保留原速母版，并在复盘里记录变速前后的数据，见 [0001](decisions/0001-no-global-speedup.md)。音频淡入淡出仅用于实际爆音或突变，不能掩盖断词。恢复被删词句按 [L-009](lessons/L-009-rebuild-script-from-library.md) 处理。

定稿前对剪后逐字稿做一遍 [滑梯检查](viewer-flow.md#7-剪完的滑梯检查)。出口：意思完整、顺序讲得通、剪口听起来自然。需审看时给具体版本；已授权一路完成时自行通过此门，不再索取同一确认。大改前保留可恢复版本。

## 5. 素材、布局与效果样张

把已核验的资料绑定剪后语义窗口，来源登记与实际入片位置一一对应。对照需求表补齐关键资料；缺口明确标记，不把下载文件当作入片完成。

讲解画面从 [explainer-kit](../templates/explainer-kit/README.md) 取组件，先找一个贯穿全片的主线视觉。按视觉编辑指南选择静态画面或最少必要动效，先做一段代表性样张：检查本片实际使用的原片、人物、资料、字幕、遮挡和平台安全区；没有或不需要的层不添加。实际合成后检查字号、停留时间、进出点、遮挡与移动过程，再批量处理同类段落。

放行门（观点 / 知识讲解片）：选 3 个代表段（一个整屏讲解、一个叠在口播上、一个本片最复杂的），用 [视频评分卡](video-scorecard.md) 跑 `lint.js` 和对标板，没有 P0、主观分达标才批量。操作教程片和纯录屏段只需过 `lint.js` 的 P0。批量后对成片跑 `score_video.py`，把分数记进项目 `review.md`。

代表段怎么出样片：kit 场景先单独 `render.js` 渲染并跑 `lint.js`；放进 ChatCut 时间线后，用 `preview_timeline` 取这一段的帧（单帧范围出全分辨率图），存成图片给对标板（`reference_board.py --ours 帧1.jpg 帧2.jpg …`）。需要连续看时，在 ChatCut 里复制一条只含这一段的临时时间线导出审看草稿。

讲解场景进 ChatCut：整屏场景渲染成 mp4，叠加层渲染成透明 `.mov`，`push_asset` 导入后放在 A-roll 上方的轨道，起点对齐剪后时间。

音乐、音效在画面定下后铺，规则见 [声音](sound.md)。

效果表不是数量指标。每张新增贴图都需有具体理解收益；泛化“个人经验”声明、重复限定与来源不默认做大卡。连续看一段检查打断和遮挡，删掉后仍讲得清的优先删。

人物缩窗、局部放大和黑边处理都要检查关键 UI 是否保留。技术问题见 [交付参考](../skills/video-to-platform-package/references/chatcut-delivery.md)，不把某片的自然盒尺寸、props、像素或资产 ID 固化为创作规则。

## 6. 正常字幕、强调、更正与隐私

从定稿时间线生成普通字幕。先确定版式、字号和行数，再做最终文本纠错；若改样式触发重新分卡，再查首尾残字及受影响时段。普通字幕保留原话，强调按关键词出现的声音时机设计，解释和更正使用独立层。

必要事实补充在相应句子附近出现，停留到能够正常读完；个人经历的语境已明确时不重复补卡。关键错误删改或具体交用户决定补录，不能依靠小字否定强烈错误口播。隐私另列区域和时间段，独立遮挡、跟随变换，检查开始、移动、切换、结束及相邻帧。

出口：普通字幕能跟听，效果不争抢注意力，资料用途准确，私密信息在已查范围内不可读。修改语音或布局后复查关联字幕、效果、来源卡和遮挡。

## 7. 封面、文案与独立审稿

按发布 Skill 准备新提示词、比例构图及平台标题简介。先看缩略图和用户真实观看尺寸，再判断信息层级；自然口吻、具体观看理由，不把经验写成保证。

按 [独立观众审稿](content-packaging/independent-reviewer.md) 提供标题、封面和成片／终稿，审稿者不先读作者答案。审稿要看片：先导出一版审看草稿（文件名带“审看”和版本号，不当最终版），给新上下文的审稿 Agent 草稿的逐秒抽帧联系表、SRT 和标题封面；它发现的 P0/P1 修完后再做第 8 步的最终导出。记录具体时间和问题；P0/P1 修完后复查受影响范围。仅审逐字稿不能判定口型、音画、动效或隐私已经通过。

## 8. 导出与最终文件检查

导出前自查关键剪口、字幕、资料覆盖、更正和隐私，按用户指定分辨率导出。所有改动定下来再导出；同一时间只保留一个导出任务，文件名带版本号。导出后又改了工程，要告诉用户旧文件已作废，并取消或忽略旧任务，不让两个版本同时出现在用户面前。

声音在成片上整体检查：跑 `score_video.py` 看响度、峰值和静音占比，目标见 [声音](sound.md)（约 −16 LUFS、峰值不超过 −1 dBTP）。用户说“人声小”，先压背景音乐、确认人声做主轨的闪避（ducking），再对成片做响度标准化，不只把人声拉高到削波。剪辑工具里做不了的处理（如美颜）交给专门工具，交付时写明哪一版是母版、哪一版是后期处理版。排队、预计路径或工具成功消息不代表文件完成；等待完成后检查实际分辨率、时长、帧率、音轨、字幕版本和完整解码，保留最终校验值与 SRT。

最终文件至少检查开头、中段、结尾、每处新改动及相关动态区间。下列结果分开记录：

| 检查 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 参数与完整解码 | 文件规格与可解码性 | 正确内容、自然听感或隐私 |
| 时间映射 | 字幕／剪辑区间计算对应 | 识别正确、实际视觉或听感 |
| 静态抽样 | 指定帧的文字、构图、遮挡 | 动效过程、音画同步、全片隐私 |
| 区间播放与试听 | 已播放区间的连续效果 | 未播放部分 |
| 连续整片检查 | 实际检查过的整片范围 | 平台审核或传播效果 |

没有连续检查就如实保留范围，不伪造“全片试听通过”。若发现具体未解决的高优先问题，修复后再交付；已通过且没有新问题的部分不反复重做。

## 9. 发布、回执与收尾

仅上传已核验的最终文件，按已授权的平台和可见 UI 操作；封面裁剪、标题正文、声明及公开范围分别读回。逐站取得提交结果、管理状态、作品或管理链接和截图；区分未知、验证阻断、审核中和已发布。未知结果先查同名作品，不盲目重投。具体规则由发布 Skill 维护。

交付成片、逐平台状态和剩余动作。按授权清理失败／废弃版本与测试音视频，先确认最终文件可用且工程依赖完整；保留原片、工程和来源，记录清理对象和释放空间。写项目复盘、真实 metrics 和台账；查现有规则的归属，直接合并修订，工具坑放技术参考。没有真实数据不宣称某效果提升了完播率。
